Tema 1.1

Modelado de Lenguaje Autoregresivo

A nivel conceptual y matemático, un Large Language Model es una función probabilística paramétrica. Su objetivo es tomar una secuencia de tokens de entrada (el contexto) y calcular la distribución de probabilidad acumulada del siguiente token más plausible.

P(w_n | w_1, ..., w_{n-1}) = Softmax(z_n / Temperature)
El Hiperparámetro de Temperatura
La Temperatura (T) escala los logits antes del Softmax. Un valor bajo (T < 0.3) hace al modelo determinista y conservador; un valor alto (T > 0.8) aplana la curva distribucional promoviendo creatividad y variabilidad.
pytorch_inference_sample.py PyTorch
import torch import torch.nn.functional as F logits = model(input_ids).logits[:, -1, :] # Forma: [batch_size, vocab_size] probs = F.softmax(logits / temperature, dim=-1) next_token = torch.multinomial(probs, num_samples=1)

Tema 1.2

El Pipeline de NLP & Transformación a Tensores

Las unidades de procesamiento gráfico (GPUs) y aceleradores como TPU o NPU ejecutan operaciones algebraicas de multiplicación de matrices sobre tensores de punto flotante. El Procesamiento de Lenguaje Natural (NLP) es el puente de ingeniería que traduce texto crudo en tensores densos estructurados.

Arquitectura del Flujo de Datos
1. Tokenización: Mapea sub-palabras a IDs numéricos enteros.
2. Embedding Lookup: Recupera vectores densos de dimensión d_model.
3. Transformer Layers: Multiplica matrices de pesos de atención y FFN.
4. Un-embedding: Proyecta los tensores al espacio del vocabulario.

Tema 2.1

Segmentación BPE (Byte-Pair Encoding)

Meta Llama 3 adopta un tokenizador BPE optimizado con un vocabulario extendido de 128,000 tokens (comparado con 32,000 en Llama 2). Esta ampliación reduce hasta un 15% el conteo de tokens en español y código, acelerando la inferencia y reduciendo el consumo de memoria KV Cache.

tokenization_example.py Python / Hugging Face
from transformers import AutoTokenizer tokenizer = AutoTokenizer.from_pretrained("meta-llama/Meta-Llama-3-8B") tokens = tokenizer.tokenize("¡Meta Llama 3!") ids = tokenizer.encode("¡Meta Llama 3!") print("Tokens:", tokens) # ['¡', 'Meta', 'ĠLlama', 'Ġ3', '!'] print("IDs:", ids) # [14781, 10582, 38125, 220, 0]

Tema 2.2

Embeddings & Álgebra Vectorial

Cada token se mapea a un vector denso de alta dimensionalidad (dimensiones de embedding d_model = 4096 en Llama 3 8B, 8192 en Llama 3 70B). En este espacio métrico continuo, la afinidad semántica se evalúa formalmente con la similitud coseno.

Cosine Similarity(u, v) = (u · v) / (||u|| ||v||)
Linealidad Semántica & Propiedades Emergentes
Vector("Rey") - Vector("Hombre") + Vector("Mujer") ≈ Vector("Reina").
Las relaciones sintácticas y semánticas se preservan como vectores de traslación espacial.

Arquitectura Transformer & Atención

Tema 3.1

Mecanismo de Auto-Atención (Self-Attention)

La auto-atención permite que cada token evalúe la relevancia contextual de todos los demás tokens de la secuencia en paralelo. Mediante las proyecciones de Query (Q), Key (K) y Value (V), el modelo asigna pesos dinámicos normalizados.

Attention(Q, K, V) = Softmax( (Q · K^T) / sqrt(d_k) ) · V
Grouped-Query Attention (GQA) en Llama 3
Llama 3 8B utiliza 32 cabezas de Query agrupadas sobre 8 cabezas de Key/Value. Esta arquitectura GQA reduce el tamaño de la memoria KV Cache en 4x, permitiendo soportar ventanas de contexto de hasta 128k tokens sin saturar la VRAM.

Tema 3.2

Leyes de Escala & Cálculo de Memoria VRAM

La memoria VRAM necesaria para inferencia se calcula multiplicando el número de parámetros por la precisión de cuantización (ej. 2 bytes por parámetro en FP16, 1 byte en INT8, 0.5 bytes en INT4) más el buffer de KV Cache para el contexto.

VRAM_Inferencia (GB) ≈ (Parámetros × Bytes_Precisión) × 1.2 + KV_Cache
  • Llama 3 8B (INT4 Cuantizado): Requiere solo ~5.5 GB de VRAM, ejecutable en laptops o GPUs domésticas.
  • Llama 3 70B (INT4 Cuantizado): Requiere ~40 GB de VRAM (ejecutable en 2x RTX 3090/4090 o Mac M-Series con 64GB).
  • Llama 3 405B (FP16): Requiere ~810 GB de VRAM en un clúster de 8x H100.

Soberanía Tecnológica & Inferencia Local

Tema 4.1

Modelos Abiertos (Open Weights) vs APIs Centralizadas

La disponibilidad de pesos abiertos permite a ingenieros y organizaciones mantener el control total sobre su infraestructura, eliminando riesgos de fuga de datos, caídas de servicio y tarifas variables por llamada a API.

Gobernanza y Cumplimiento
Los pesos abiertos garantizan privacidad total, cumplimiento de normativas de datos sensibles (GDPR / HIPAA) y personalización profunda mediante fine-tuning (LoRA / QLoRA).
