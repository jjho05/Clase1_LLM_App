MÓDULO 2 TEMA 4 · PROYECTO INTEGRADOR & PRODUCCIÓN

Proyecto Integrador

Despliegue de un agente completo en WhatsApp con Llama Guard, alta disponibilidad y telemetría. Integra todas las capas de la arquitectura: la Cloud API, la memoria persistente, la estandarización con Llama Stack, las llamadas a funciones operativas y la moderación con Llama Guard 3 en un servidor continuo con dominio HTTPS y observabilidad 24/7.

Guía de Inicio · Visión de la Unidad 2.4

Resumen Ejecutivo (TL;DR) & Estándares de Grado Industrial

1. Resumen Ejecutivo De la Prueba de Concepto a la Operación Real

Llevar un agente de IA a producción exige abandonar los túneles locales de ngrok y desplegar un servidor continuo en la nube (VPS en AWS, GCP o Azure) con un dominio público y certificado SSL gestionado por NGINX. Ningún agente empresarial debe publicarse sin una capa de seguridad: Llama Guard 3 clasifica entradas y salidas bajo 14 categorías de riesgo, mientras que Prompt Guard neutraliza inyecciones de prompt y jailbreaks antes de que alcancen el modelo principal.

La operación profesional se sostiene en la telemetría continua: monitorear la tasa de entrega de webhooks, vigilar la latencia percentil $p95$ (<3s), rastrear el costo por conversación y contar con un plan de contingencia con colas de reintento y circuit breakers ante fallas en la Graph API de Meta.

Las 5 Capas de la Solución Integrada
1. Cloud API
Webhooks verificados con HMAC-SHA256 y canal de salida en Graph API.
2. Memoria & Stack
Sesiones aisladas por wa_id en Redis/SQLite con sliding window.
3. Tool Calling
Invocación segura de funciones de negocio con esquemas JSON Schema.
4. Blindaje Shield
Moderación bidireccional con Llama Guard 3 y Prompt Guard.
5. Infra & Telemetría
Docker Compose, NGINX SSL, métricas p95 y circuit breakers.
Tema 2.4.1 · Síntesis Arquitectónica

Unión de Todas las Piezas: La Arquitectura Completa de Producción

1. El Pipeline Unificado El Viaje Completo de un Mensaje

En el proyecto integrador, el sistema opera como una cadena de montaje de alta precisión:

  1. Recepción Segura: Meta envía el webhook HTTP POST a tu dominio HTTPS. NGINX valida TLS 1.3 y reenvía a FastAPI.
  2. Autenticación Criptográfica & Idempotencia: FastAPI verifica la cabecera X-Hub-Signature-256 con tu App Secret y consulta Redis para confirmar que el wamid no sea un duplicado.
  3. Capa 1 de Seguridad (Prompt Guard): Se analiza el texto del usuario para descartar ataques de inyección de prompt o jailbreaks.
  4. Capa 2 de Seguridad (Llama Guard 3): Se clasifica el mensaje bajo las 14 categorías de riesgo. Si infringe alguna regla, se cancela el pipeline.
  5. Recuperación de Estado: Se consulta SQLite/Redis para extraer el historial reciente y las variables del usuario (wa_id).
  6. Inferencia 1 & Tool Calling: Llama 3 procesa el prompt y decide si invocar una herramienta (ej. consultar_disponibilidad).
  7. Ejecución Segura: El backend ejecuta la función contra la base de datos real.
  8. Inferencia 2 & Filtro de Salida: Llama 3 sintetiza la respuesta y Llama Guard 3 verifica la salida antes de despacharla.
  9. Despacho: Envío inmediato a WhatsApp Graph API con código HTTP 200.

Tema 2.4.2 · Blindaje & Seguridad

Seguridad en Producción: Llama Guard 3 vs. Prompt Guard

1. Especialización de Modelos Dos Guardianes con Misiones Distintas

No todos los riesgos son iguales. Meta desarrolló dos modelos complementarios para proteger agentes en entornos hostiles:

Característica Prompt Guard 86M Llama Guard 3 1B / 8B
Misión Principal Detección de inyecciones de prompt directas/indirectas y jailbreaks (intentos de evadir las instrucciones del sistema). Clasificación semántica de seguridad bajo la taxonomía de 14 categorías de riesgo (S1 a S14).
Arquitectura Clasificador basado en BERT/RoBERTa ultraligero (86 millones de parámetros). Modelo de lenguaje autoregresivo basado en Llama 3 con prompting de seguridad.
Latencia de Inferencia Ultra-baja (5 a 15 ms en CPU/GPU). Baja (30 a 60 ms en GPU con KV cache).
Posición en el Pipeline Primera línea de defensa: evalúa el texto crudo del usuario. Segunda línea de defensa (entrada) y última línea de defensa (salida).

Tema 2.4.3 · Despliegue de Infraestructura

Del ngrok Local al Servidor Continuo: NGINX, SSL y Docker

1. Requisitos de Producción Dominio Público y Certificado TLS Válido

Meta exige estrictamente que la URL de webhook en producción utilice HTTPS con un certificado SSL válido emitido por una autoridad certificadora reconocida (como Let's Encrypt o DigiCert). No se permiten certificados autofirmados.

La topología estándar de despliegue utiliza Docker Compose con contenedores orquestados:

  • Contenedor NGINX: Escucha en los puertos 80/443, gestiona la renovación automática de SSL mediante Certbot y aplica Rate Limiting (máximo 50 peticiones/segundo por IP).
  • Contenedor FastAPI (Gunicorn/Uvicorn): 4 workers asíncronos para procesar la lógica de negocio y los webhooks en paralelo.
  • Contenedor Redis: Persistencia en memoria para idempotencia (wamid) y colas de reintento con TTL de 24h.
  • Contenedor vLLM / Inferencia: Servidor de inferencia optimizado para Llama 3 con soporte de GPU.

Tema 2.4.4 · Observabilidad & Telemetría

Monitoreo, Telemetría y SLAs: Los 4 Indicadores Clave (KPIs)

1. Latencia Percentil p95 (< 3.0s)

El 95% de las respuestas de tu agente deben entregarse en menos de 3 segundos. Si el p95 supera los 4.5s, se disparan alertas automáticas a DevOps.

2. Tasa de Entrega Webhooks (> 99.8%)

Porcentaje de webhooks respondidos con HTTP 200 en menos de 3s. Meta puede degradar la calidad del número si la tasa de errores 5xx supera el 1%.

3. Tasa de Fallo en Herramientas (< 2%)

Frecuencia con la que una llamada a función (Tool Call) genera parámetros inválidos o excepciones de base de datos.

4. Costo y Tokens por Conversación

Seguimiento del volumen de tokens procesados y cálculo del costo de inferencia por cada interacción resuelta con el cliente.

Ejercicios Prácticos Oficiales de la Unidad 2.4

      
Resuelve los 4 casos integradores de arquitectura, moderación y contingencia del temario oficial.

    


    
    

      

        Ejercicio 1
        
Diagrama de Arquitectura del Proyecto Integrador

      

      

        Dibuja el diagrama de flujo completo del agente integrando: WhatsApp Cloud API, servidor continuo, Llama Guard (entrada y salida), Llama 3, la base de datos externa y la llamada de respuesta. Señala los puntos donde el flujo puede bifurcarse por una regla fija o por una violación de seguridad.
      

      
      

        
Solución de Ingeniería:

        

          Topología del Pipeline: WhatsApp -> NGINX (SSL) -> FastAPI (HMAC + Redis Idempotencia) -> Llama Guard 3 (Entrada) -> [Bifurcación 1: Violación UNSAFE -> Bloqueo] -> Enrutador Híbrido [Bifurcación 2: Regla Fija -> Transferencia Humana] -> Inferencia Llama 3 (Tool Calling) -> DB Externa -> Inferencia Final Llama 3 -> Llama Guard 3 (Salida) -> Graph API WhatsApp.
        

      

    


    
    

      

        Ejercicio 2
        
Configuración de la Política de Seguridad con Llama Guard

      

      

        Define qué categorías de Llama Guard deben bloquearse para un agente de atención a clientes en un comercio electrónico (por ejemplo, fraude, asesoramiento legal no autorizado o contenido violento) y redacta el mensaje de política que recibirá el usuario si activa un filtro de seguridad.
      

      
      

        
Solución de Ingeniería:

        

          Categorías Bloqueadas: S1 (Crimen Violento), S2 (Sustancias Ilícitas), S9 (Inyecciones de Prompt), S14 (Extracción de PII Financiera).
          


          Mensaje Neutral de Política: "Por políticas de seguridad y privacidad de nuestra tienda, no puedo procesar este tipo de solicitudes. Si necesitas asistencia con un pedido o producto, con gusto te ayudo."
        

      

    


    
    

      

        Ejercicio 3
        
Plan de Despliegue y Monitoreo para Producción

      

      

        Elabora una lista de verificación (checklist) con los pasos para pasar de ngrok a un servidor continuo: aprovisionamiento de VPS, configuración de NGINX, certificado SSL, variables de entorno seguras y configuración de alertas de latencia.
      

      
      

        
Solución de Ingeniería:

        

          Checklist de Producción:
          
1. VPS Ubuntu 24.04 LTS en AWS/GCP con IP estática fija.
          
2. Dominio DNS apuntado con registro A y NGINX con Certbot SSL automático.
          
3. Archivo .env fuera del control de versiones con permisos chmod 600.
          
4. Uvicorn con 4 workers supervisados por Systemd con Restart=always.
          
5. Dashboard Prometheus/Grafana con alertas a Slack si $p95 > 3.5s$ durante 3 minutos consecutivos.
        

      

    


    
    

      

        Ejercicio 4
        
Plan de Contingencia ante Fallas de la API de WhatsApp

      

      

        Diseña el protocolo de contingencia si la Graph API de Meta sufre una interrupción de 15 minutos: qué responde el servidor al webhook para no saturar la cola, cómo se guardan los mensajes pendientes y cómo se procesan al reanudarse el servicio.
      

      
      

        
Solución de Ingeniería:

        

          El webhook siempre responde HTTP 200 OK a Meta para evitar cancelaciones. Si el despacho de salida falla con error 5xx de Graph API, el mensaje procesado se guarda en una cola Redis (LPUSH pending_outbox). Un proceso Celery con retroceso exponencial reintenta el envío cada 30 segundos hasta que la Graph API se restablezca.
        

      

    


  


  
  

    

      
Diccionario de Conceptos

      
Glosario Técnico Oficial · Unidad 2.4

      
Conceptos clave sobre seguridad en producción, Llama Guard, servidores continuos y telemetría.

    


    

      
      
      

        
        
        
        
      

    


    

      
      

        
Llama Guard

        

          Modelo de clasificación de seguridad desarrollado por Meta para evaluar entradas y salidas de modelos de lenguaje, detectando contenido inapropiado o violaciones bajo 14 categorías estandarizadas.
        

      


      

        
Prompt Guard

        

          Modelo clasificador ultraligero (86M de parámetros) diseñado para detectar inyecciones de prompt directas e indirectas y técnicas de jailbreak antes de invocar al modelo principal.
        

      


      

        
Servidor Continuo

        

          Infraestructura de alojamiento permanente (VPS en la nube) que opera de forma ininterrumpida las 24 horas del día con dirección IP fija o dominio público, a diferencia de los túneles locales de ngrok.
        

      


      

        
Certificado SSL / TLS

        

          Credencial criptográfica que cifra la comunicación HTTPS entre los servidores de Meta y tu servidor backend, requisito obligatorio para verificar y activar webhooks en producción.
        

      


      

        
Monitoreo de Agentes

        

          Supervisión en tiempo real de la salud del sistema: latencia p95, tasas de error en webhooks, consumo de tokens y calidad de las respuestas conversacionales.
