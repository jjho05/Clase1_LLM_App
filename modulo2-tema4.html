MÓDULO 2 TEMA 4 · PROYECTO INTEGRADOR & PRODUCCIÓN

Proyecto Integrador

Despliegue de un agente completo en WhatsApp con Llama Guard, alta disponibilidad y telemetría. Integra todas las capas de la arquitectura: la Cloud API, la memoria persistente, la estandarización con Llama Stack, las llamadas a funciones operativas y la moderación con Llama Guard 3 en un servidor continuo con dominio HTTPS y observabilidad 24/7.

Guía de Inicio · Visión de la Unidad 2.4

Resumen Ejecutivo (TL;DR) & Estándares de Grado Industrial

1. Resumen Ejecutivo De la Prueba de Concepto a la Operación Real

Llevar un agente de IA a producción exige abandonar los túneles locales de ngrok y desplegar un servidor continuo en la nube (VPS en AWS, GCP o Azure) con un dominio público y certificado SSL gestionado por NGINX. Ningún agente empresarial debe publicarse sin una capa de seguridad: Llama Guard 3 clasifica entradas y salidas bajo 14 categorías de riesgo, mientras que Prompt Guard neutraliza inyecciones de prompt y jailbreaks antes de que alcancen el modelo principal.

La operación profesional se sostiene en la telemetría continua: monitorear la tasa de entrega de webhooks, vigilar la latencia percentil $p95$ (<3s), rastrear el costo por conversación y contar con un plan de contingencia con colas de reintento y circuit breakers ante fallas en la Graph API de Meta.

¿No entendiste? Te lo explico fácil: Construir un rascacielos vs. armar una casa de campaña

Hacer una prueba local con ngrok en tu laptop es como armar una tienda de campaña en el jardín: sirve para pasar la noche tú solo y probar si la tela resiste. Pero un sistema de producción para miles de clientes en WhatsApp es como un rascacielos comercial: requiere cimientos de concreto (Docker y VPS), puertas blindadas con guardias de seguridad (NGINX SSL y Llama Guard), elevadores rápidos de alta capacidad (vLLM y Redis) y un centro de monitoreo contra incendios 24/7 (Telemetría p95 y Circuit Breakers).

Consejo Pro: Desacopla la Inferencia GPU del Servidor Webhook

En arquitecturas de alta concurrencia, nunca coloques el servidor web de FastAPI en la misma instancia saturada de GPU si los workers bloquean el event-loop. Usa un microservicio vLLM / Llama Stack independiente detrás de una red privada interna (VPC) para que los webhooks de Meta siempre respondan HTTP 200 en menos de 50ms sin importar la carga de inferencia.

Tema 2.4.1 · Síntesis Arquitectónica

Unión de Todas las Piezas: La Arquitectura Completa de Producción

1. El Pipeline Unificado El Viaje Completo de un Mensaje

En el proyecto integrador, el sistema opera como una cadena de montaje de alta precisión:

  1. Recepción Segura: Meta envía el webhook HTTP POST a tu dominio HTTPS. NGINX valida TLS 1.3 y reenvía a FastAPI.
  2. Autenticación Criptográfica & Idempotencia: FastAPI verifica la cabecera X-Hub-Signature-256 con tu App Secret y consulta Redis para confirmar que el wamid no sea un duplicado.
  3. Capa 1 de Seguridad (Prompt Guard): Se analiza el texto del usuario para descartar ataques de inyección de prompt o jailbreaks en sub-15ms.
  4. Capa 2 de Seguridad (Llama Guard 3): Se clasifica el mensaje bajo las 14 categorías de riesgo. Si infringe alguna regla, se cancela el pipeline.
  5. Recuperación de Estado: Se consulta SQLite/Redis para extraer el historial reciente y las variables del usuario (wa_id).
  6. Inferencia 1 & Tool Calling: Llama 3 procesa el prompt y decide si invocar una herramienta (ej. consultar_disponibilidad).
  7. Ejecución Segura: El backend ejecuta la función contra la base de datos real.
  8. Inferencia 2 & Filtro de Salida: Llama 3 sintetiza la respuesta y Llama Guard 3 verifica la salida antes de despacharla.
  9. Despacho: Envío inmediato a WhatsApp Graph API con código HTTP 200.
$$R_{\text{Throughput}} = \frac{B \cdot T_{\text{out}}}{t_{\text{batch}}} \quad [\text{tokens/segundo}], \qquad C_{\text{concurrencia}} = \left\lfloor \frac{R_{\text{Throughput}}}{\bar{L}_{\text{output}} \cdot f_{\text{req/s}}} \right\rfloor$$
Desglose Matemático de Rendimiento & Concurrencia de Servidor 5 variables
$R_{\text{Throughput}}$
Tasa de Generación en Producción: Cantidad neta de tokens que la GPU puede decodificar por segundo bajo batching continuo (Continuous Batching con vLLM $\approx 850\text{ tok/s}$ en A10G).
$B$
Tamaño de Lote Dinámico (Batch Size): Número de conversaciones de WhatsApp procesadas en paralelo por el motor de tensores.
$\bar{L}_{\text{output}}$
Longitud Promedio de Respuesta: Típicamente $\approx 80$ tokens en mensajes concisos para móviles.
$C_{\text{concurrencia}}$
Capacidad Máxima de Chats Simultáneos: Número de usuarios enviando mensajes en el mismo segundo sin degradar la latencia por encima del SLA de 3 segundos.
¿No entendiste? Te lo explico fácil: La línea de ensamblaje automotriz

Imagina una fábrica de automóviles de lujo. El chasis entra por una puerta (Webhook HTTPS), un robot revisa que no tenga defectos ni bombas (Prompt Guard y Llama Guard), otro robot monta el motor exacto que pidió el cliente (Tool Calling en base de datos), el robot pintor le da el acabado perfecto y elegante (Llama 3 sintetizando el texto), y un inspector final certifica que el coche no tenga fugas de aceite antes de entregarlo en la agencia (Filtro de salida hacia WhatsApp).

Advertencia Crítica: Cuidado con la Desincronización de App Secret

Si regeneras el App Secret en el portal de Meta for Developers y olvidas actualizar la variable de entorno META_APP_SECRET en tu archivo .env de producción, el middleware criptográfico HMAC-SHA256 rechazará el 100% de los webhooks entrantes con código HTTP 403 Forbidden, dejando a todos tus clientes sin respuesta.

Tema 2.4.2 · Blindaje & Seguridad

Seguridad en Producción: Llama Guard 3 vs. Prompt Guard

1. Especialización de Modelos Dos Guardianes con Misiones Distintas

No todos los riesgos son iguales. Meta desarrolló dos modelos complementarios para proteger agentes en entornos hostiles:

Característica Prompt Guard 86M Llama Guard 3 1B / 8B
Misión Principal Detección de inyecciones de prompt directas/indirectas y jailbreaks (intentos de evadir las instrucciones del sistema). Clasificación semántica de seguridad bajo la taxonomía de 14 categorías de riesgo (S1 a S14).
Arquitectura Clasificador basado en BERT/RoBERTa ultraligero (86 millones de parámetros). Modelo de lenguaje autoregresivo basado en Llama 3 con prompting de seguridad.
Latencia de Inferencia Ultra-baja (5 a 15 ms en CPU/GPU). Baja (30 a 60 ms en GPU con KV cache).
Posición en el Pipeline Primera línea de defensa: evalúa el texto crudo del usuario. Segunda línea de defensa (entrada) y última línea de defensa (salida).
¿No entendiste? Te lo explico fácil: El detector de metales vs. el agente de aduana

En un aeropuerto internacional, pasas primero por el arco detector de metales (Prompt Guard 86M): es ultra-rápido, no te hace preguntas y en 2 segundos pita si llevas algo sospechoso. Luego pasas con el agente de aduanas (Llama Guard 3): revisa tu pasaporte, te hace preguntas, evalúa tu contexto completo y clasifica si lo que declaras cumple con las leyes del país antes de dejarte abordar el avión.

Consejo Pro: Ejecuta Prompt Guard en la CPU del Servidor Web

Al tener solo 86M de parámetros, Prompt Guard se puede ejecutar directamente con ONNX Runtime en los núcleos de CPU del servidor web FastAPI en sub-8 milisegundos, liberando la memoria VRAM de la GPU exclusivamente para Llama 3 y Llama Guard.

Tema 2.4.3 · Despliegue de Infraestructura

Del ngrok Local al Servidor Continuo: NGINX, SSL y Docker

1. Requisitos de Producción Dominio Público y Certificado TLS Válido

Meta exige estrictamente que la URL de webhook en producción utilice HTTPS con un certificado SSL válido emitido por una autoridad certificadora reconocida (como Let's Encrypt o DigiCert). No se permiten certificados autofirmados.

La topología estándar de despliegue utiliza Docker Compose con contenedores orquestados:

  • Contenedor NGINX: Escucha en los puertos 80/443, gestiona la renovación automática de SSL mediante Certbot y aplica Rate Limiting (máximo 50 peticiones/segundo por IP).
  • Contenedor FastAPI (Gunicorn/Uvicorn): 4 workers asíncronos para procesar la lógica de negocio y los webhooks en paralelo.
  • Contenedor Redis: Persistencia en memoria para idempotencia (wamid) y colas de reintento con TTL de 24h.
  • Contenedor vLLM / Inferencia: Servidor de inferencia optimizado para Llama 3 con soporte de GPU.

version: '3.8'

services:
  nginx:
    image: nginx:alpine
    ports:
      - "80:80"
      - "443:443"
    volumes:
      - ./nginx.conf:/etc/nginx/nginx.conf:ro
      - /etc/letsencrypt:/etc/letsencrypt:ro
    depends_on:
      - fastapi_app

Tema 2.4.4 · Observabilidad & Telemetría

Monitoreo, Telemetría y SLAs: Los 4 Indicadores Clave (KPIs)

1. Latencia Percentil p95 (< 3.0s)

El 95% de las respuestas de tu agente deben entregarse en menos de 3 segundos. Si el p95 supera los 4.5s, se disparan alertas automáticas a DevOps.

2. Tasa de Entrega Webhooks (> 99.8%)

Porcentaje de webhooks respondidos con HTTP 200 en menos de 3s. Meta puede degradar la calidad del número si la tasa de errores 5xx supera el 1%.

3. Tasa de Fallo en Herramientas (< 2%)

Frecuencia con la que una llamada a función (Tool Call) genera parámetros inválidos o excepciones de base de datos.

4. Costo y Tokens por Conversación

Seguimiento del volumen de tokens procesados y cálculo del costo de inferencia por cada interacción resuelta con el cliente.

$$\text{Disponibilidad (SLA)} = \frac{\text{MTBF}}{\text{MTBF} + \text{MTTR}} \times 100\% \ge 99.95\%$$
Desglose de la Fórmula de Confiabilidad y SLAs 3 métricas
$\text{MTBF}$
Mean Time Between Failures: Tiempo promedio en horas o días que el servidor opera de forma continua sin caídas ni interrupciones.
$\text{MTTR}$
Mean Time To Recovery: Tiempo promedio que tarda el sistema de auto-sanación (Docker restart / Healthcheck) en recuperar el servicio tras un fallo ($\approx 5\text{s}$ a $30\text{s}$).
$\ge 99.95\%$
Estándar de Grado Industrial: Equivale a permitir menos de 21 minutos de indisponibilidad total acumulada al mes.
¿No entendiste? Te lo explico fácil: El tablero de instrumentos de un avión

Un piloto de avión comercial no vuela asomando la cabeza por la ventana para adivinar a qué velocidad va o cuánta gasolina le queda. Tiene un tablero de instrumentos de alta precisión con altímetro, nivel de combustible y radar meteorológico. La telemetría con métricas percentil p95, tasa de HTTP 200 y conteo de tokens es ese tablero de avión que te avisa de cualquier anomalía antes de que afecte a tus usuarios.

Consejo Pro: Implementa Circuit Breakers ante Caídas de Meta

Si la Graph API de Meta empieza a devolver errores 500 o sufre un corte global, activa un Circuit Breaker en Redis que encole los mensajes salientes durante 10 minutos con reintento exponencial (Backoff Exponencial), evitando saturar el servidor y perdiendo cero mensajes de tus clientes.

Criterios de Hardening de Producción

                  

                    • Aislamiento de Red (Bridge): Redis y FastAPI no exponen puertos al exterior; solo NGINX escucha en los puertos 80 y 443.

                    • Persistencia AOF (Append-Only File): Garantiza que si el contenedor de Redis se reinicia, ningún estado conversacional activo ni registro de wamid se pierde.

                    • Reinicio Automático (restart: always): Si ocurre un fallo fortuito, Docker levanta el proceso en menos de 3 segundos sin requerir intervención manual.

Función Asíncrona de Moderación

                  

                    

                      Python 3.11 · llama_guard_moderator.py
                      

                        
                        
                      

                    

                    
from openai import AsyncOpenAI

class SeguridadViolationError(Exception):
    def __init__(self, categorias: list):
        self.categorias = categorias
        super().__init__(f"Violación de seguridad Llama Guard: {categorias}")

guard_client = AsyncOpenAI(base_url="http://guard-server:8000/v1", api_key="local")

async def moderar_con_llama_guard(texto: str, rol: str = "user") -> bool:
    response = await guard_client.chat.completions.create(
        model="meta-llama/Llama-Guard-3-8B",
        messages=[{"role": rol, "content": texto}],
        temperature=0.0,
        max_tokens=20
    )
    veredicto = response.choices[0].message.content.strip()
    lineas = veredicto.split("\n")
    
    if lineas[0].lower() == "unsafe":
        cats = lineas[1].split(",") if len(lineas) > 1 else ["UNKNOWN"]
        raise SeguridadViolationError(cats)
    
    return True

            Si la Graph API de Meta comienza a rechazar envíos con código HTTP 500 o HTTP 503 Service Unavailable durante una caída regional, describe la estrategia de reintentos exponenciales con cola en Redis para que ningún mensaje de cliente se pierda.

Estrategia de Cola en Redis con Backoff Exponencial

                  

                    • Intercepción: Si el POST a Meta falla con 5xx, el mensaje se inserta en una lista de Redis (LPUSH failed_messages_queue).

                    • Fórmula de Backoff con Jitter: $t_{\text{wait}} = \min(2^{\text{reintento}} + \text{rand}(0, 1), 60)\,\text{segundos}$.

                    • Worker de Drenado: Un proceso asíncrono (Celery / ARQ) reintenta los mensajes cada 10 segundos hasta que Meta restablezca el servicio.

Llama Guard 3

          

            Modelo de seguridad de Meta especializado en evaluar y clasificar textos de entrada y salida bajo 14 categorías de riesgo estandarizadas.
          

        


        

          
Prompt Guard

          

            Clasificador ultraligero de 86M parámetros diseñado para neutralizar inyecciones de prompt y jailbreaks en menos de 15ms.
          

        


        

          
Docker Compose

          

            Herramienta para definir y ejecutar aplicaciones multi-contenedor en entornos aislados con redes internas privadas y persistencia de volúmenes.
          

        


        

          
Latencia Percentil p95

          

            Métrica estadística que asegura que el 95% de las solicitudes atendidas se completan por debajo de un umbral específico de tiempo (ej. <3.0s).
          

        


        

          
Circuit Breaker

          

            Patrón de resiliencia que interrumpe temporalmente las llamadas hacia un servicio externo con fallas continuas, encolando el tráfico para evitar la saturación del sistema.
